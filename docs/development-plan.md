# 开发前置与分阶段验证

> 本文为此前图谱路线的验证计划，暂不执行。当前范围调整为 frontmatter / Properties，见 [当前属性架构](frontmatter-architecture.md)。

状态：历史建议计划，不用于描述当前进度。当前属性原型已实现并验证，见 [验证记录](prototype-verification.md)。

## 1. 开发前固定的契约

按 [架构建议](architecture.md) 的方向，首个原型应固定以下边界：

| 项目 | 推荐的初始范围 |
| --- | --- |
| 索引对象 | 明确启用 HTML Graph 元数据的 `.html/.htm` 文件 |
| 标签来源 | 版本化的 JSON 元数据块 |
| 文件关系 | 带显式标记的 HTML 超链接，初期目标为 HTML/HTM/Markdown |
| 图谱 | 原生全局与局部图谱，开启附件；标签边要求开启标签 |
| 阅读 | 复用已有 HTML 阅读器，不注册同名扩展 |
| 文件写入 | 首个原型只读源文件 |
| 原生功能 | 不将全文检索、属性编辑、反链面板、预览与筛选视为自动支持 |
| 平台 | 首先验证 Windows + Obsidian 1.14.4；Android 另设验证阶段 |

HTML 元数据命名与显式链接规则是推荐草案，应在写原型前明确接受或调整，避免实现后反复更换笔记格式。

## 2. 工具链准备建议

正式启动原型时再创建：

- `package.json` 与 lockfile。
- TypeScript 配置、esbuild 配置和实验 manifest。
- 官方 Obsidian 类型依赖；HTML 解析器按既定源码位置需求引入。
- 轻量的类型检查、构建和有意义的解析测试命令。

首个实验包仅声明已验证的版本与平台范围。不要把当前版本写成“最低版本”后就宣称所有更高版本均已兼容，也不要把桌面成功等同于 Android 成功。

项目仓库名保留。manifest ID 不能包含 `obsidian`，开发库插件目录名应与 ID 一致；发布名称与 ID 在创建 manifest 前确定。

无需服务器、数据库、UI 框架或全文索引框架。构建工具和版本组合应先验证，不能照搬所有依赖的 `latest`。

## 3. 阶段 A：独立测试环境

建立项目内被 Git 忽略的独立测试库，只放合成材料：

- 三份相互关联的 HTML，其中至少一条未解析关系。
- 一份 Markdown，链接到 HTML，并作为 HTML 的目标。
- 重名文件、中文与空格路径、页内锚点、嵌套标签。
- 导航、资源和外链，用于证明它们不会误入知识关系。
- 一份无效元数据与一份未启用适配的 HTML。

不得复制个人笔记、课件或日常库配置到测试库。阅读器通过独立安装或明确的本地发布包准备，避免共享日常库插件状态。

## 4. 阶段 B：最小只读原型

先只连接必要链路：解析 → 内存索引 → 原生兼容层 → 图谱。

真实应用验收要求：

1. 从图谱界面看到正确的 HTML 节点、文件边和标签边。
2. 点击文件节点打开对应 HTML，当前阅读器继续工作。
3. 全局与局部图谱均能观察到正确关系；若局部图谱无法以 HTML 为中心，明确记录缺口。
4. 修改 HTML 后关系更新；快速连续保存不由旧任务覆盖新结果。
5. 删除、改名、移动后无残留旧实线，未解析关系与源文件实际状态一致。
6. 插件停用后图谱回到原有 HTML 支持状态，源文件哈希不变。
7. 重启与反复加载/卸载不会累积包装、监听器或旧关系。
8. 与现有阅读器一起启用时，无扩展名注册冲突。
9. Markdown/Canvas 的已有关系不被覆盖；忽略文件的规则得到尊重。
10. 不支持的接口或插件冲突能给出明确诊断，不部分启用。

用图谱截图、CLI 查询以及源码哈希共同作证。`resolvedLinks` 有值、模拟函数通过或仅出现节点，都不能替代以上验收。

此阶段改名只要求索引正确反映改名后的现实；不承诺自动修复 HTML 原文中的失效 URL。

## 5. 阶段 C：兼容与可维护性

在只读链路通过后，补齐：

- 方法包装的所有权、其他插件包装顺序及安全撤销。
- 原生重解析、尚未完成的任务、停用和重启之间的竞争。
- 精确 HTML 路径语义与 Obsidian 模糊匹配的差异。
- 默认图谱之外的过滤、分组及标签面板行为；按实际需求决定是否支持。
- 无 HTML 阅读器、替换阅读器、图谱核心插件关闭等情况。
- 规模扩大后的扫描与事件合并，不进行每次保存全库重扫。

发布前才讨论扩大兼容版本范围。接口缺失时停用适配并说明原因，不能静默生成辅助 Markdown。

## 6. 阶段 D：精确改名与移动写回

只有只读原型可用后再实现。应先明确用户是否需要自动写回，以及与 Obsidian 自动更新链接偏好的关系。

必要验收：

- 目标改名、来源移动、整个目录移动和连续多次改名。
- 中文、URL 编码、实体、单双引号及片段保持正确。
- 属性范围以 UTF-16 源码位置为准，并验证 emoji 等非 BMP 字符情况。
- 不整体序列化 HTML；无关脚本、样式、排版保持原样。
- 源文件在计划与写入之间变化时，取消或重新计算。
- 保留更新前证据并提供明确的撤销路径。
- 不把内核生成的 Markdown 替换字符串写进 HTML 属性。

通过这一阶段之前，不能宣称插件可以可靠维护改名后的 HTML 链接。

## 7. 阶段 E：Android

在真实 Android Obsidian 和已选阅读器上验证同一索引、图谱和生命周期。

同步时传输 HTML 与插件发布文件；派生索引按设备重建，避免同步索引数据库。桌面开发脚本、机器路径和 Node/Electron API 不进入移动端运行逻辑。

桌面移动模拟可辅助调试布局，不能代替设备验证。

## 8. 当前交付与下一步

本轮交付了架构建议、接口证据、只读探查工具和离线原生函数验证结果，没有创建插件功能、项目依赖、实验 manifest 或测试库。

下一项最值得开展的工作是：固定 HTML v1 声明契约和实验范围，然后在独立测试库中验证最小只读桥接。若该阶段证明内核接入成本超过预期，再以证据讨论路线调整。
