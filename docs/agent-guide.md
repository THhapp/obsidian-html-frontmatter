# Agent 读写约定

适用于当前 HTML Frontmatter 0.1.2 的文件格式。能读写本地文件的 Agent 可以直接维护属性，无需启动 Obsidian 或操作界面；在 Obsidian 中显示、编辑和统计这些属性，需要启用兼容版本的插件。当前支持桌面 Obsidian 1.14.4。

## 新建笔记

从 [HTML 模板](../templates/note.html) 复制到任务授权的目标位置，再填写标题、正文和需要的属性。模板只预置空 `tags` 列表，不强制课程、状态或日期等业务字段。

属性块推荐放在 `<head>` 内：

```html
<script type="application/json" id="obsidian-frontmatter">
{
  "课程": "数据库",
  "完成": false,
  "tags": ["课程/数据库"]
}
</script>
```

HTML 中嵌入 JSON 使用 [HTML 标准的数据块机制](https://html.spec.whatwg.org/multipage/scripting.html#the-script-element)；`obsidian-frontmatter` 这个标识和属性规则是本插件的约定，不是其他软件自动识别的通用 frontmatter 协议。数据离开插件后仍可提取为 JSON。

## 文件格式

| 项目 | 约定 |
| --- | --- |
| 文件 | `.html` 或 `.htm`；新建使用 UTF-8，修改现有文件保留换行与周围源码 |
| 数据块 | 活动文档中只能有一个 `id="obsidian-frontmatter"` 的 `<script type="application/json">`，必须有结束标签；不要放进注释或 `<template>` |
| 内容 | 严格 JSON 对象，双引号、无注释、无尾逗号；不在 HTML 顶部添加 YAML `---` 块 |
| 属性值 | 字符串、有限数字、布尔值、`null`，或这些基础值组成的一层数组；不支持嵌套对象和嵌套数组 |
| 属性名 | 不得为空，不使用 `__proto__`、`constructor`、`prototype` |
| 特殊字段 | `tags`、`aliases`、`cssclasses` 必须是字符串数组，空值用 `[]`；标签建议不带开头的 `#`，嵌套标签使用 `/` |
| 日期 | 保存为字符串，如 `2026-10-16`、`2026-10-16T09:30:00`；不要自行改换时区，原生日期类型设置不全保存在此块内 |

数字和布尔值不要加引号。缺失字段、空字符串、空数组和 `null` 含义不同；删除属性应移除键，不应擅自改成 `null`。未要求修改的字段应保留。

写入前用 JSON 序列化器生成数据，再将 `<` 转义为 `\u003c`，将 U+2028、U+2029 转义为 `\u2028`、`\u2029`，与现有写入器一致。特别是字符串中的结束标签，必须写成 `\u003c/script>`；不要使用 `&lt;` 等 HTML 实体替代 JSON 转义。

## 修改现有笔记

1. 读取目标文件，定位并校验数据块。已有块无效、重复、类型错误或缺少结束标签时，停止修改该文件并说明原因，不自动重建或覆盖。
2. 以原属性为基线，只更新任务指定的键。写入前重新读取当前源码，将变更合并到最新数据中；同一字段已有冲突时，不用旧值覆盖。
3. 只替换数据块的 JSON 内容，保留块外字符，包括正文、样式、脚本、注释和标签属性。不要通过整个 DOM 的重新序列化保存一次属性修改。
4. 如果没有数据块，仅在任务确实需要写入属性时插入一个；不把所有 HTML 批量初始化。属性维护任务不修改正文。
5. 写完重新解析属性，并核对块外源码是否保留。反馈修改的文件和字段，不把磁盘写入成功说成图谱、搜索或 UI 已验证。

普通文件写入不会自动使用插件的写入队列，也不具备跨进程事务保证。同一文件尽量由一个写入者处理，避免 Agent 和人工同时编辑同一个字段。

仓库已有 [src/metadata.ts](../src/metadata.ts) 可复用；这些是源码函数，不是已安装插件提供的 CLI、MCP 或独立 SDK：

| 函数 | 用途 |
| --- | --- |
| `readMetadata(source)` | 读取属性、定位源码区间并拒绝无效块 |
| `writeMetadata(source, properties)` | 校验完整目标属性，仅替换 JSON 内容或插入缺失块，并处理转义 |
| `diffProperties(before, after)` | 计算相对初始属性的字段变更，保留“缺失”和 `null` 的区别 |
| `applyChanges(latestSource, changes)` | 将字段变更应用到最新源码，保留其他字段更新，同字段冲突则报错 |

只调用 `writeMetadata` 并传入旧的完整属性对象，不能保留并发发生的其他字段修改；有外部编辑时应使用字段差异合并。

## 可复制给笔记 Agent 的短约定

```text
本任务的 HTML 属性遵循 HTML Frontmatter 约定：在 head 中使用唯一的
<script type="application/json" id="obsidian-frontmatter"> 数据块，内容为扁平 JSON 对象。
只读写任务授权的目标文件；新建为 UTF-8 编码的完整 HTML 文档。tags、aliases、cssclasses
必须是字符串数组，其他值为基础值或一层基础值数组，不随意改变原有字段类型。
修改已有属性时保留未指定字段，写入前重读并检查冲突，只改 JSON 内容，保留块外源码。
序列化时将 < 写成 \u003c，避免字符串提前结束 script 数据块。
数据块重复、损坏或字段发生冲突时停止该文件的写入，并报告原因。
全局属性改名或删除、正文阅读、图谱和搜索适配不在此约定范围。
```

此短约定可放进笔记库自己的 `AGENTS.md` 或任务提示。项目根目录的 `AGENTS.md` 是插件开发约定，无需整份复制过去。
